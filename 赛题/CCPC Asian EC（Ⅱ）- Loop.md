# CCPC Asian EC（Ⅱ）- Loop

## 讲解

这一道题目中的输入的数字可以看作一个环形的跑道，一直往前走（索引 +1）到超过他的长度后会回到开头，同理反方向走的话走到开头也会自动回到结尾。
可以观察到，我们要从原本第一个数字不断往右或者往下走，并且由于这个地图是由原来给出的数字得到的，因此其实往右走一步就相当于在跑道中往左走一格，往下就相当于在跑道中往右走一格，此时题目的要求就相当于从头开始走，中途需要选择往左或往右最后回到起点，然后找出途径的格子上数字和最小的路径。
根据题目的要求，往一个方向（比如正方向）走了多少，就得往回走多少，并且总的步数一定是2n-2步（n为数组的长度），那么一个方向只能走n-1步，并且，我们在走的时候会走到一个点M，到了这个点后如果前面已经走过的和是最小的，那么直接原路返回（相当于原路返回，因为网格是关于右上到左下连成的对角线对称的）后总和就会是最小的，也就是说我们在找和最小的路径时，往右走的n-1步，在后一半也是原路返回的
那么想要得到答案，可以很自然地想使得走到点M的路径是最短的，那么我们只需要把每一个M的位置的和求出来然后比较就可以得到最小值了，M的位置可以是数组第2个数字到最后一个数字，不能是第一个数字，因为第一个数字是起点，一旦走了一步就越过了这个数字，他就不是最远点了
为了方便，我们用每个格子出现的次数来表示步数，那么总的要走的格子数为2n-1（格子数=步数+1，比如从格子1走到格子2需要一步，实际上走了两个格子），走的索引路径为：0, 1, 2 ... M - 1, M , M - 1, ... ,2 ,1 ,0 ，在这之中，0~M-1各出现两次，共2M格，M出现一格，那么总共为2M+1格，那么就会多出来2n-1-(2M+1) =2n-2M-2=2(n-M-1) ，那么多出来的格子就可以在M与M-1直接左右横跳（相当于在真正的地图中不断向右向下走），需要横跳n-M-1次，每一次M与M-1出现次数都+1，这样就可以凑齐2(n-M-1)了。
有了路径就可以求每个总和了，我们用a[n]代表第n个索引的数值，那么
- 0 ~ M - 2 出现了 2*(M-1)次
- M - 1 出现了 2 + n - M - 1 = n - M + 1 次
- M 出现了 1 + n - M - 1 = n - M 次
总和res = 2*(a[0]+...+a[M-2]) + (n-M+1)*a[M-1] + (n-M)*a[M]
把每一个M对应的res都求出来找最小值即可。
注意：当M为1时，从0~M-2的就不需要计数了，因为M-1为0，这一步结果为0
由于到M的方式有正向和反向两种，所以正向反向都需要求一次res，而反向只需要将数组除了第一个数字以外的数字全部倒转即可，与索引一直减等价，如3 1 2 4要求反向时只需要改为3 4 2 1再用正向的方法求即可，不改变第一个数字是因为起点不会改变。

接下来以3 1 2 4这一组数据为例，当M为2（索引为2）时，总的格子数为2n-1=7，则路径为：
0 1 2 1 2 1 0 
0 ~ M - 2 的值为 2*3 = 6
M - 1 的值为 (4 - 2 + 1)*1 = 3
M 的值为 (4 - 2)*2 = 4
结果为13，此时可以暂存，再把其它的M求完后获取最小值

示例代码：
// ConsoleApplication83.cpp : 此文件包含 "main" 函数。程序执行将在此处开始并结束。
//

#include <iostream>
#include <vector>
#include <math.h>
using namespace std;

void cal(vector<long long>& num, vector<long long>& pre, long long& res) {
	int n = num.size();
	for (int i = 1; i < n; i++) {
		long long sum = 0;
		if (i == 1) {
			sum = (n * (num[0]) + (n - i) * (num[i]));
		}
		else {
			long long step1 = 0;
			/*for (int j = 0; j < i - 1; j++) {
				step1 += num[j];
			}*/
			step1 = pre[i - 1];
			sum = 2 * step1 + (n - i) * num[i] + (n - i + 1) * num[i - 1];
		}
		res = min(res, sum);
	}
}

int main()
{
	int t;
	cin >> t;
	while (t--) {
		int n;
		cin >> n;

		vector<long long> num(n, 0);
		vector<long long> pre(n + 1, 0);
		for (int i = 0; i < n; i++) {
			cin >> num[i];
			pre[i + 1] = pre[i] + num[i];
		}
		
		if (n == 1) {
			cout << num[0] << "\n";
			continue;
		}

		long long res = 9223372036854775807;

		cal(num, pre, res);

		reverse(num.begin() + 1, num.end());
		for (int i = 1; i <= n; i++) {
			pre[i] = pre[i - 1] + num[i - 1];
		}

		cal(num, pre, res);

		cout << res << "\n";
	}
}

你推导出的候选路径出现次数公式是正确的：0~M-2 出现两次，M-1 出现 n-M+1 次，M 出现 n-M 次，并正确实现了前缀和优化。

你处理了反向枚举，并且代码中考虑了 n=1、long long、多测，说明你不仅停留在口头理解，也把实现细节走通了。

发现的问题

你说“到了点 M 后如果前面已经走过的和是最小的，那么直接原路返回后总和就会最小”，这是错误或至少严重不严谨。候选总和不是由前缀和最小决定，而是由 2*sum(0..M-2)+(n-M+1)*a[M-1]+(n-M)*a[M] 决定；M 会影响 a[M-1] 和 a[M] 的重复次数，前缀和最小不代表总候选和最小。

“原路返回，因为网格关于右上到左下对角线对称”这个说法容易误导。网格路径只允许右/下，不允许左/上；你的一维索引序列看起来像“返回”，但在网格中必须重新分配右/下步数，变成合法路径。对称性不能直接证明路径合法。

“往一个方向走了多少，就得往回走多少”过度简化。准确说法是总下步数 = 总右步数 = n-1，对应一维环上 +1 次数和 -1 次数相等，均为 n-1。路径不一定先单向再返回，虽然最优可化为这种结构，但需要证明。

你断言最优路径一定形如先到某个 M，再折返，剩余在 M 与 M-1 之间横跳，但没有给出证明。这是本题最重要的“为什么枚举 M 就够”的部分，不能只靠观察。

M 的范围你说成“第2个数字到最后一个数字”，结论对，但理由“一旦走了一步就越过了这个数字”很模糊。需要形式化说明 M 是一维正向最远点，至少为 1，且 n=1 要特判。

你没有讨论 a_i 是否非负。材料只写 integer，如果存在负数，重复负值可能影响最优结构，公式是否仍覆盖最优需要额外说明或证明。

你说“a[n] 代表第 n 个索引的数值”有歧义。数组长度是 n，索引通常为 0 到 n-1，应写 a[k] 或 a[i]。

复杂度没有讲清楚。你的 cal 是每个测试 O(n)，配合 sum n ≤ 2×10^5，总复杂度 O(sum n)，这是能过的关键，但讲解中没点明。
